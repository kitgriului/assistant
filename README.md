## 🎯 О проекте

GuardBot - это комплексное решение для управления системой пропусков на охраняемой территории. Бот автоматизирует весь цикл работы с заявками: от подачи посетителем до выдачи QR-кода и контроля прохода охранниками.

### Для кого этот проект?

- **Охранные компании** - автоматизация учета посетителей
- **Офисные центры** - управление пропускной системой
- **Производственные предприятия** - контроль доступа на территорию
- **Жилые комплексы** - регистрация гостей

- Аутентификация через Telegram (номер телефона)

### Требования

- Python 3.12+
- SQLite

### Установка

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/yourusername/guardbot.git
cd guardbot

# 2. Создайте виртуальное окружение
python3.12 -m venv venv
source venv/bin/activate  # Linux/macOS
# .\venv\Scripts\activate  # Windows PowerShell

# 3. Установите зависимости
pip install -r requirements.txt

# 4. Настройте переменные окружения
cp .env.example .env
# Отредактируйте .env и добавьте BOT_TOKEN

# 5. Запустите бота
python start_bot.py
```

### Docker (рекомендуется для production)

```bash
# 1. Клонируйте и настройте
git clone https://github.com/yourusername/guardbot.git
cd guardbot
cp .env.production .env
nano .env  # Добавьте BOT_TOKEN

# 2. Запуск
docker compose up -d

# 3. Просмотр логов
docker compose logs -f
```

## 🎯 Описание

GuardBot - это комплексная система управления пропусками на территорию, которая обеспечивает:

- **Бесконтактную подачу заявок** через Telegram
- **Безопасную аутентификацию** через номер телефона
- **Быстрое одобрение** заявок администраторами и охранниками
- **QR-коды** для бесконтактной идентификации на КПП
- **Раздельные пропуска** для пешеходов и автомобилей

## ⚡ Реализованный функционал

### 👥 Роли пользователей

#### 1. **Guest (Заявитель)**
Возможности:
- 📝 Подача заявок на пропуск (пешеход/автомобиль)
- 📅 Выбор даты и времени визита через календарь
- 🎯 Выбор цели визита из готовых шаблонов
- 📷 Загрузка фото документов
- 🚗 Указание номера автомобиля (для транспорта)
- 📱 Получение QR-кода для предъявления

Процесс подачи заявки:
```
/start → 📝 Подать заявку 
   → Тип: 🚶 Пешеход / 🚗 Автомобиль
   → Цель: готовые варианты или свой текст
   → Дата: интерактивный календарь
   → Время: 8:00-20:00 (шаг 30 мин)
   → [Для авто: номер машины]
   → Фото документа/тех.паспорта
   → Получение QR-кода
```

Шаблоны целей для пешехода:
- 👔 Деловая встреча
- 📦 Получение груза
- 🚚 Доставка
- ✏️ Другое (свой текст)

Шаблоны целей для автомобиля:
- 🚛 Погрузка/разгрузка
- 🚚 Доставка
- 🚗 Служебная поездка
- ✏️ Другое (свой текст)

#### 2. **Guard (Охранник)**
Возможности:
- 📋 Просмотр заявок на утверждение
- ✅ Утверждение заявок
- ❌ Отклонение заявок
- 📸 Просмотр фото документов
- 🔍 Детальная информация по каждой заявке
- 🚶 **Обход территории**:
  - Создание обхода с контрольными точками
  - Фото с камеры (только реальная съемка!)
  - Геолокация на точках
  - Текстовые заметки
  - Статистика обхода в реальном времени

Процесс обработки заявок:
```
/start → 📋 Заявки на утверждение
   → Просмотр списка pending-заявок
   → [Просмотр фото] / [Утвердить] / [Отклонить]
   → Генерация QR-кода при утверждении
```

Процесс обхода территории:
```
/start → 🚶 Новый обход
   → Добавить точку обхода
   → [📸 Фото с камеры] - можно несколько
   → [📍 Геолокация] - опционально
   → [📝 Заметка] - опционально
   → Завершить точку
   → [Добавить еще точки или завершить обход]
   → Статистика: время, точки, фото
```

#### 3. **Admin (Администратор)**
Возможности всех ролей +
- 👥 Управление пользователями
- 🔐 Изменение ролей (admin/guard/guest)
- 🚫 Блокировка/разблокировка пользователей
- 📊 Просмотр всех зарегистрированных пользователей

Процесс управления:
```
/start → 👥 Управление пользователями
   → Список всех пользователей
   → [Изменить роль] / [Заблокировать/Разблокировать]
```

### 🔄 Паттерны и принципы

**Router Pattern (aiogram 3.x)**
- Каждый модуль имеет свой Router
- Роутеры регистрируются в главном Dispatcher
- Изолированная обработка команд и callback'ов

**FSM (Finite State Machine)**
- Пошаговое заполнение заявок
- Состояния хранятся в памяти (aiogram FSM)
- Автоматическая очистка при завершении/отмене

**Async/Await**
- Полностью асинхронная архитектура
- Неблокирующие операции с БД
- Параллельная обработка запросов

**Separation of Concerns**
- Handlers: обработка команд и callback'ов
- Models: структура данных
- Utils: вспомогательные функции
- States: определение FSM состояний

## 🐛 Устранение неполадок

### Частые проблемы

#### 1. Ошибка токена
```
TokenValidationError: Token is invalid!
```
**Решение**: Проверить токен в `.env` файле

#### 2. Конфликт соединений
```
Conflict: terminated by other getUpdates request
```
**Решение**: Остановить все экземпляры бота, подождать 5 минут

#### 3. ServerDisconnectedError
```
TelegramNetworkError: Server disconnected
```
**Решение**: Нормальное поведение, бот автоматически переподключается
