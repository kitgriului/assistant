# 🚀 Инструкция по запуску обновлённой системы GuardBot

## Что изменилось в Этапе 1

### ✅ Реализовано:

1. **Система аутентификации и ролей**
   - 3 роли: `guest` (гость), `guard` (охранник), `admin` (администратор)
   - Охранники и админы логинятся через логин/пароль
   - Гости регистрируются с указанием ФИО

2. **Новые модели БД:**
   - `User` расширен: добавлены поля для аутентификации
   - `Request` расширен: связь с пользователем, статусы, QR-коды
   - `PatrolEvent` - события обхода
   - `PatrolCheckpoint` - точки обхода с геолокацией
   - `CheckpointPhoto` - фотографии на точках
   - `PatrolQuestion` - вопросы администратора
   - `PatrolAnswer` - ответы охранника

3. **Новые утилиты:**
   - `utils/auth.py` - хеширование паролей (bcrypt)
   - `utils/roles.py` - проверка ролей и декораторы

4. **Новые обработчики:**
   - `handlers/auth.py` - процесс авторизации
   - Обновлён `handlers/applicant.py` - работа с новой системой

## 📋 Пошаговая инструкция запуска

### Шаг 1: Установка зависимостей

```bash
pip install -r requirements.txt
```

Основная новая зависимость: **bcrypt** (для хеширования паролей)

### Шаг 2: Настройка переменных окружения

Убедитесь, что файл `.env` содержит:

```env
BOT_TOKEN=your_bot_token_here
DB_URL=sqlite+aiosqlite:///./guardbot.db
```

### Шаг 3: Инициализация пользователей

Создайте начальных пользователей (админов и охранников):

```bash
python init_users.py init
```

Это создаст:
- **admin** / admin123 - Администратор системы
- **guard1** / guard123 - Охранник 1
- **guard2** / guard123 - Охранник 2

⚠️ **ВАЖНО:** Смените пароли после первого входа!

### Шаг 4: Запуск бота

```bash
python run_bot.py
```

или через модуль:

```bash
python -m bot.main
```

## 👥 Сценарии использования

### Для гостей (новый пользователь):

1. Отправить `/start` боту
2. Ввести ФИО
3. Готово! Можно подавать заявки через `/request`

### Для охранников/администраторов:

1. Отправить `/start` боту
2. Ввести логин (например: `guard1`)
3. Ввести пароль (например: `guard123`)
4. Авторизация успешна!

### Команды по ролям:

**Гость:**
- `/request` - подать заявку на пропуск
- `/help` - справка

**Охранник:**
- `/pending` - список заявок на утверждение
- `/approve <ID>` - утвердить заявку
- `/reject <ID>` - отклонить заявку
- `/start_patrol` - начать обход
- `/my_patrols` - мои обходы
- `/questions` - вопросы от администратора

**Администратор:**
- `/users` - список пользователей
- `/requests [status]` - список заявок
- `/events` - список событий обхода
- `/event <ID>` - детали события
- `/ask <event_id> <вопрос>` - задать вопрос охраннику
- `/stats` - статистика

## 🗄️ Структура БД

### User (пользователи)
- `telegram_id` - ID в Telegram
- `role` - роль (guest, guard, admin)
- `name` - ФИО
- `login` - логин (для guard/admin)
- `password_hash` - хеш пароля
- `is_authenticated` - флаг аутентификации
- `last_login` - время последнего входа

### Request (заявки)
- `applicant_id` - связь с User
- `name`, `purpose`, `datetime`, `photo` - данные заявки
- `status` - статус (pending, approved, rejected, used, expired)
- `processed_by_id` - кто обработал
- `processed_at` - когда обработано
- `rejection_reason` - причина отклонения
- `qr_code` - уникальный код для QR

### PatrolEvent (события обхода)
- `guard_id` - охранник
- `started_at`, `completed_at` - время обхода
- `status` - in_progress, completed, cancelled
- `notes` - заметки

### PatrolCheckpoint (точки обхода)
- `event_id` - связь с событием
- `checkpoint_number` - номер точки
- `latitude`, `longitude` - геолокация
- `timestamp` - время отметки
- `notes` - заметки

### CheckpointPhoto (фото на точках)
- `checkpoint_id` - связь с точкой
- `photo_path` - путь к файлу
- `description` - описание

## ⚠️ Важные примечания

1. **База данных:** При первом запуске все таблицы создаются автоматически
2. **Миграция:** Если у вас уже есть данные, потребуется миграция БД
3. **Пароли:** Используйте надёжные пароли в production
4. **Telegram ID:** Для guard/admin устанавливается автоматически при первом входе

## 🐛 Устранение неполадок

### Ошибка: "пользователь не найден"
- Запустите `python init_users.py init` для создания пользователей
- Проверьте правильность логина

### Ошибка: "неверный пароль"
- Проверьте правильность пароля
- Убедитесь, что используете пароль, заданный при создании

### Бот не отвечает
- Проверьте токен в `.env`
- Убедитесь, что бот запущен
- Проверьте логи
