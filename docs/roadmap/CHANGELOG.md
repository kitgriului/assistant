# 📝 История изменений GuardBot

## [Версия 0.10.0] - 2025-11-01 (Функционал патрулирования)

### ✨ Новый функционал
- **🚶 Система обхода территории для охранников**:
  - Возможность начать новый обход через меню
  - Добавление произвольного количества точек обхода
  - На каждой точке можно:
    - 📸 Добавить несколько фотографий (только с камеры!)
    - 📍 Добавить геолокацию
    - 📝 Добавить текстовую заметку
  - Защита от подделки: принимаются только фото с камеры
  - Статистика обхода в реальном времени
  - Возможность продолжить незавершенный обход

### 🗄️ База данных
- Используются существующие таблицы:
  - `patrol_events` - события обхода
  - `patrol_checkpoints` - точки обхода
  - `checkpoint_photos` - фотографии на точках
  - `patrol_questions` - вопросы администраторов
  - `patrol_answers` - ответы охранников

### 🎯 FSM состояния
- Добавлены состояния в `PatrolStates`:
  - `in_patrol` - обход активен
  - `waiting_checkpoint_action` - ожидание действия на точке
  - `waiting_photo` - ожидание фото с камеры
  - `waiting_location` - ожидание геолокации
  - `waiting_notes` - ожидание заметок

### 📱 Интерфейс
- Новая кнопка "🚶 Новый обход" в меню охранника
- Интерактивное меню управления обходом
- Статистика с детализацией по точкам
- Защита от случайного выхода из обхода

## [Версия 0.9.0] - 2025-11-01

### ✨ Добавлено
- **🔔 Уведомления заявителям** (Priority 1 из roadmap):
  - При утверждении: текст + QR-код
  - При отклонении: текст с причиной
- **🎫 QR-коды с deep links**:
  - Формат: `https://t.me/SK_GuardBot?start=pass_{ID}_{UUID}`
  - При сканировании открывается бот с полной информацией о пропуске
  - Показывается статус, срок действия, история обработки
- **⏰ Система истечения пропусков**:
  - 2 часа с момента утверждения
  - Поле `valid_until` в БД
  - Автоопределение expired при просмотре
- **📊 Подменю "Управление заявками"** для админов и охраны:
  - 📋 Заявки на утверждение
  - ✅ Активные пропуска (с оставшимся временем)
  - 📦 Архивные пропуска (последние 20)
- **🔍 Просмотр активных пропусков**:
  - Фильтр по `valid_until > now` и `status=approved`
  - Отображение оставшегося времени
- **📦 Архив заявок**:
  - Статусы: rejected, expired, used
  - Последние 20 записей

### 🔄 Изменено
- **Структура главного меню**:
  - Админ: Управление заявками | Управление пользователями | Подать заявку
  - Охранник: Управление заявками
  - Гость: Подать заявку на пропуск
- **QR-коды теперь с повышенной надёжностью**:
  - `error_correction=ERROR_CORRECT_H` (30% восстановление)
  - `box_size=10`, `border=4`
- **Навигация**:
  - Кнопка "◀️ Назад" ведёт в подменю "Управление заявками"
  - Из подменю "◀️ Назад" ведёт в главное меню

### 🐛 Исправлено
- Ошибка `NoneType.strip()` при пропуске текста в `request_purpose()`
- Добавлена проверка `if not message.text:` перед обработкой
- Улучшена обработка ошибок при отправке уведомлений

### 📝 Документация
- Обновлён `STATUS.md` - актуальный статус v0.9.0
- Обновлён `TECHNICAL_SUPPLEMENT.md` - описание QR deep links
- Обновлён `ROADMAP.md` - отмечен прогресс

## [Версия 1.0.0] - 2025-10-22

### ✅ Реализованные функции

#### 🤖 Основной функционал
- **Telegram Bot интеграция** с aiogram 3.x
- **Асинхронная архитектура** для высокой производительности
- **FSM (Finite State Machine)** для пошагового заполнения форм
- **SQLAlchemy ORM** для работы с базой данных
- **QR-код генерация** для заявок

#### 👥 Роли пользователей
- **Заявители (Applicant)**: подача заявок, получение QR-кодов
- **Администраторы (Guard)**: одобрение заявок, патрулирование
- **Клиенты (Client)**: просмотр отчетов, экспорт данных

#### 📋 Команды бота
- `/start`, `/help` - справка и приветствие
- `/request` - подача заявки на пропуск
- `/approve <ID>` - одобрение заявки администратором
- `/patrol` - система патрулирования
- `/list_requests` - список всех заявок
- `/export_requests` - экспорт данных

#### 🗄️ База данных
- **Модель User**: пользователи системы
- **Модель Request**: заявки на пропуски
- **Модель Patrol**: журнал патрулирования
- **Модель Media**: медиафайлы

#### 🛠️ Утилиты
- **QR генератор** (`utils/qr.py`)
- **Обработка медиа** (`utils/media.py`)
- **Экспорт данных** (`utils/export.py`)

### 🔧 Исправленные проблемы

#### 22.10.2025 - Исправление критических ошибок

**Проблема #1: Синтаксическая ошибка в guard.py**
- ❌ **Проблема**: Отсутствовал перенос строки между функциями
- ✅ **Решение**: Добавлена пустая строка между `register_guard_handlers` и `cmd_approve`

**Проблема #2: Неактивные обработчики команд**
- ❌ **Проблема**: Основные обработчики были закомментированы в `handlers/__init__.py`
- ✅ **Решение**: Активированы все обработчики для applicant, guard и client

**Проблема #3: Echo-обработчик блокировал команды**
- ❌ **Проблема**: Echo-обработчик перехватывал все команды
- ✅ **Решение**: Изменен фильтр для исключения команд, начинающихся с `/`

**Проблема #4: Ошибки aiogram 3.x совместимости**
- ❌ **Проблема**: `UnsupportedKeywordArgument: content_types`
- ✅ **Решение**: Удален параметр `content_types` из регистрации обработчиков

**Проблема #5: InputFile ошибка**
- ❌ **Проблема**: `Can't instantiate abstract class InputFile`
- ✅ **Решение**: Заменен `InputFile` на `FSInputFile` во всех файлах

**Проблема #6: HTML parsing ошибка**
- ❌ **Проблема**: `can't parse entities: Unsupported start tag "id"`
- ✅ **Решение**: Заменены угловые скобки `<>` на квадратные `[]` в сообщениях

**Проблема #7: Проблемы с импортами**
- ❌ **Проблема**: `ModuleNotFoundError: No module named 'database'`
- ✅ **Решение**: Добавлен `sys.path.insert` в `main.py` для корректных импортов
