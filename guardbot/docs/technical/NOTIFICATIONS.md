## 📋 Описание

Система автоматических уведомлений заявителям о статусе их заявок на пропуск.

## ✅ Реализованный функционал

### 1. Уведомление при утверждении заявки

**Когда срабатывает:**
- Охранник или админ нажимает "✅ Утвердить" на заявке

**Что получает заявитель:**

1. **Текстовое сообщение:**
```
✅ Ваша заявка #{ID} УТВЕРЖДЕНА!

📋 Детали пропуска:
🚶/🚗 Тип: Пешеход/Автомобиль
📝 Цель: [цель визита]
🚗 Номер авто: [если указан]
📅 Дата и время: [дата визита]

👮 Утвердил: [ФИО охранника]

💡 Важно: Сохраните QR-код ниже для предъявления на КПП.
```

2. **QR-код пропуска** (отдельным сообщением)
```
🎫 Ваш пропуск #{ID}

Предъявите этот QR-код на КПП
```

**Техническая реализация:**
```python
# handlers/guard.py, функция callback_approve()

# Получаем заявителя
applicant = await session.get(User, req.applicant_id)

# Отправляем уведомление
await callback.bot.send_message(
    chat_id=applicant.telegram_id,
    text=applicant_text,
    parse_mode="HTML"
)

# Отправляем QR-код
await callback.bot.send_photo(
    chat_id=applicant.telegram_id,
    photo=FSInputFile(qr_path),
    caption="🎫 Ваш пропуск..."
)
```

### 2. Уведомление при отклонении заявки

**Когда срабатывает:**
- Охранник или админ нажимает "❌ Отклонить" на заявке

**Что получает заявитель:**

**Текстовое сообщение:**
```
❌ Ваша заявка #{ID} отклонена

📋 Детали заявки:
🚶/🚗 Тип: Пешеход/Автомобиль
📝 Цель: [цель визита]
🚗 Номер авто: [если указан]
📅 Дата и время: [дата визита]

📝 Причина отклонения:
[причина от охранника]

👮 Обработал: [ФИО охранника]

💡 Вы можете подать новую заявку через /start
```

**Техническая реализация:**
```python
# handlers/guard.py, функция callback_reject()

# Получаем заявителя
applicant = await session.get(User, req.applicant_id)

# Отправляем уведомление
await callback.bot.send_message(
    chat_id=applicant.telegram_id,
    text=rejection_text,
    parse_mode="HTML"
)
```

## 🔧 Техническая архитектура

### Обработка ошибок

Все уведомления обернуты в `try/except` блок:

```python
try:
    # Отправка уведомления
    await callback.bot.send_message(...)
    logger.info(f"Notification sent to {telegram_id}")
except Exception as e:
    logger.error(f"Failed to send notification: {e}")
    # Процесс не прерывается - заявка все равно утверждена/отклонена
```

**Принцип:** Если уведомление не отправилось (пользователь заблокировал бота, проблемы с сетью и т.д.), это НЕ должно влиять на основной процесс утверждения/отклонения заявки.

### Логирование

Все действия логируются:

```python
logger.info(f"Notification sent to applicant {applicant.telegram_id} for request #{req.id}")
logger.error(f"Failed to send notification to applicant: {e}")
```

### Получение заявителя

```python
# Получение из БД по applicant_id
applicant = await session.get(User, req.applicant_id)

if applicant and applicant.telegram_id:
    # Отправка уведомления
```

**Проверки:**
- ✅ Заявитель существует в БД
- ✅ У заявителя есть telegram_id
- ✅ Telegram_id валидный

## 📊 Поток данных

### Утверждение заявки

```
Охранник нажимает "✅ Утвердить"
    ↓
callback_approve(callback, state)
    ↓
Обновление статуса в БД (status = "approved")
    ↓
Генерация QR-кода
    ↓
Отправка сообщения охраннику
    ↓
Получение заявителя из БД
    ↓
Отправка уведомления заявителю (текст + QR)
    ↓
Логирование результата
```

### Отклонение заявки

```
Охранник нажимает "❌ Отклонить"
    ↓
callback_reject(callback)
    ↓
Обновление статуса в БД (status = "rejected")
    ↓
Отправка сообщения охраннику
    ↓
Получение заявителя из БД
    ↓
Отправка уведомления заявителю (причина отклонения)
    ↓
Логирование результата
```

## 🧪 Тестирование

### Как протестировать

1. **Подать заявку от имени заявителя:**
   - Открыть бота в Telegram
   - /start → "📝 Подать заявку"
   - Заполнить все поля
   - Дождаться QR-кода

2. **Утвердить заявку от имени охранника/админа:**
   - Зайти под админом
   - /start → "📋 Заявки на утверждение"
   - Нажать "✅ Утвердить"
   - **Проверить:** Заявитель получил уведомление + QR

3. **Отклонить заявку:**
   - Подать новую заявку
   - От админа отклонить
   - **Проверить:** Заявитель получил уведомление с причиной

### Сценарии проверки

#### ✅ Успешная отправка
- [ ] Заявитель зарегистрирован
- [ ] Telegram_id валидный
- [ ] Бот запущен
- [ ] Сеть работает
- **Ожидаемый результат:** Уведомление доставлено

#### ❌ Заявитель заблокировал бота
- [ ] Заявитель удалил/заблокировал бота
- **Ожидаемый результат:** 
  - Уведомление не доставлено
  - Ошибка залогирована
  - Заявка все равно утверждена/отклонена

#### ❌ Проблемы с сетью
- [ ] Временная недоступность Telegram API
- **Ожидаемый результат:**
  - Ошибка обработана
  - Процесс не прерван

## 📈 Метрики

### Что отслеживать

1. **Процент доставки:**
   - Успешных отправок / Всего попыток
   - Цель: > 95%

2. **Время доставки:**
   - От утверждения до получения
   - Цель: < 2 секунд

3. **Ошибки:**
   - Количество ошибок отправки
   - Типы ошибок (заблокирован, сеть, и т.д.)

### Логи для мониторинга

```bash
# Успешные уведомления
grep "Notification sent to applicant" guardbot.log | wc -l

# Ошибки отправки
grep "Failed to send notification" guardbot.log

# За последний час
grep "Notification" guardbot.log | grep "$(date +'%Y-%m-%d %H')"
```
